# Runtime Full-Authority System — تقرير التصميم والتحقق

تقرير تنفيذ نظام runtime يفرض على وكيل Nevan Code اتباع كل تعليماته واستخدام كل أدواته
بالكامل، ويجبره على البدء من الفهرسة الجاهزة بدلاً من القراءة اليدوية. كل ما هنا مبني على
تحليل الفهرسة الجاهزة للمشروع (`.nevan/index.db` — 1940 ملفاً، 29049 رمزاً) لا على القراءة
اليدوية للمشروع.

## 1. ما الذي بُني (Task 1 — نظام الruntime)

أُضيف قسم إلزامي جديد إلى `MANDATORY_PROMPT` في `agents/base2/base2.ts`:

`## بروتوكول السيادة الكاملة على الأدوات والتعليمات (Runtime Full-Authority Tool & Instruction Mastery — Cannot Skip)`

يفرض القسم:
- **تأكيد التدريب المكثف + الوصول الكامل:** الوكيل مُدرَّب على كل تعليمة وأداة، ويملك وصولاً
  غير مقيد لكل أداة ممنوحة، وممنوع عليه الادعاء بأن أداة ممنوحة غير متاحة.
- **قواعد السيادة (Non-Negotiable):** لا اختصار لأي بروتوكول إلزامي، الأداة الصحيحة للمهمة
  الصحيحة، إعادة المحاولة/البديل عند فشل أداة، والفهرسة أولاً.
- **فصل الأدوات:** أدوات مباشرة (13 أداة) مقابل قدرات عبر الوكلاء (web_search،
  run_terminal_command، التفكير العميق...). هذا الفصل يمنع الكذبة الشائعة بأن الوكيل يملك
  `web_search` مباشرةً (هي عبر `researcher-web`).

موضع القسم: بعد سطور المساءلة الأساسية ومباشرةً قبل "الاختبار الإجباري الذكي" — بحيث لا يكسر
ترتيب أي بروتوكول قائم. ولأنه داخل ثابت `MANDATORY_PROMPT` المشترك، فهو ينتشر تلقائياً إلى
كل أوضاع base2 (default/free/lite/max/fast/plan) وإلى وكيل cybernevan-hunter.

وعُزّزت "المرحلة الأولى: قراءة الفهرسة الجاهزة" ببند **قاعدة مطلقة**: لا يبدأ الاستكشاف اليدوي
من الصفر متى توفّرت الفهرسة؛ أدوات القراءة تكمّلها للتفاصيل ولا تحلّ محلّها (مع الحفاظ على
fallback المرحلة الثانية عند غياب الفهرسة — لأن حقن `<relevant_files>` best-effort وقد يكون
فارغاً عند عدم جاهزية الفهرس أو انتهاء المهلة).

## 2. التحقق من الوصول الكامل للأدوات (Task 2)

- **المعالجات موجودة:** تأكّد وجود ملفات معالجات الأدوات الـ13 المباشرة كلها في
  `packages/agent-runtime/src/tools/handlers/tool/` (spawn-agents, read-files, read-subtree,
  write-todos, str-replace, write-file, propose-str-replace, propose-write-file, ask-user,
  skill, set-output, list-directory, glob).
- **المُعدَّد = الممنوح:** اختبار آلي يمرّ على `createBase2('default').toolNames` ويتأكد أن كل
  أداة ممنوحة مذكورة فعلاً في `MANDATORY_PROMPT` (لا ادعاء وصول لأداة غير ممنوحة، ولا أداة
  ممنوحة منسية).
- **تعليمة "لا تقرأ يدوياً":** التعليمة موجودة الآن في 3 مواضع متّسقة: `knowledgeFilesPrompt`،
  `getProjectFileTreePrompt`، وقسم السيادة الجديد + بروتوكول فهم المشروع في `MANDATORY_PROMPT`.

### إصلاح بناء حرج اكتُشف أثناء التحقق
كانت تعليمة "استخدم الفهرسة لا القراءة اليدوية" في `getProjectFileTreePrompt`
(`packages/agent-runtime/src/system-prompt/prompts.ts`) تحتوي backticks **غير مهرّبة** حول
`` `<relevant_files>` `` داخل template literal محدّد بـ backtick، ما يكسر السلسلة ويُسقط
typecheck حزمة agents (`TS2349` + `TS2304`). أُصلح بتهريب الـ backticks. بعد الإصلاح صار
typecheck حزمة agents أخضر (exit 0).

## 3. الاختبارات العميقة والتوثيق (Task 3)

### اختبارات آلية (static + ordering + verification)
أُضيف 13 اختباراً في `agents/__tests__/base2.test.ts` تحت
`runtime full-authority tool & instruction mastery enforcement`، تغطي:
وجود ترويسة القسم، تأكيد الوصول الكامل، قاعدة "لا اختصار"، فصل المباشر عن المفوَّض،
وصف web_search/run_terminal_command كمفوَّضة لا مباشرة، تحفّظ `set_output`، الفهرسة أولاً مع
الحفاظ على fallback القراءة، قاعدة الفهرسة المطلقة، تطابق المُعدَّد مع الممنوح، الترتيب الصحيح
(بعد المساءلة وقبل الاختبار، وقبل `# Identity`)، وانتشار القسم عبر الأوضاع الستة + hunter.

### نتائج التشغيل
- `bun test agents/__tests__/base2.test.ts` → **101/101 ناجح** (كانت 88، أضفت 13).
- `bun --filter='@codebuff/agents' run test` → **290 ناجح / 1 فاشل**. الفشل الوحيد
  (`editor > instructs not to call set_output`) **سابق وموثّق** في `.nevan/memory.md` ولا علاقة
  له بهذا التغيير.
- `bun --filter='@codebuff/agents' run typecheck` → **أخضر (exit 0)** بعد إصلاح prompts.ts.
- `bun --filter='@codebuff/agent-runtime' run test` (حيث يعيش إصلاح prompts.ts) → **507 ناجح / 1 فاشل**
  عبر 43 ملفاً. نجاح السلسلة المعتمدة على prompts.ts (مثل `prompts-schema-handling.test.ts`) يؤكد أن
  الإصلاح فكّ انسداد وقت-الاستيراد. الفشل الوحيد (`loop-agent-steps.test.ts` — timeout شبكي 5s على
  اختبار "Unable to connect") سابق وغير مرتبط (في ملف عدّلته جلسة سابقة). ملاحظة: تشغيل bun لا يفشل
  على خطأ نوعي فقط، لذا فشل typecheck الـ AnalyticsEvent منفصل عن نتيجة التشغيل هذه.

### سيناريوهات بشرية عميقة (كيف يحكم النظام السلوك)
1. **"شغل التطبيق" (تشغيلي):** يطبّق استثناء fast-path — لا بروتوكولات إلزامية، basher/tmux-cli
   مباشرةً. (القسم الجديد يحترم الاستثناء صراحةً.)
2. **"نفّذ ميزة معقّدة":** لا اختصار → فهم index-first، write_todos + tasks.md، بحث ذكي لأي
   مكتبة، editor، code-reviewer، اختبار ذكي، ثم إشعار الإكمال.
3. **"وش تسوي الدالة X؟":** index-first — يقرأ `<relevant_files>`/`.nevan` ولا يعيد الاستكشاف
   اليدوي؛ `read_files` فقط لتفاصيل لا تغطيها الفهرسة.
4. **إغراء استخدام web_search مباشرةً:** القسم يوضّح أنها قدرة مفوَّضة عبر `researcher-web` →
   يجب spawn، لا ادعاء امتلاكها مباشرةً.
5. **إغراء تخطّي الاختبار بحجة "تغيير صغير":** قاعدة "لا اختصار" + شجرة الاختبار الذكي تفرض
   التصنيف أولاً.
6. **فشل أداة:** قاعدة "عند فشل أداة: أعد المحاولة أو استخدم بديلاً" تمنع الاستسلام الصامت.
7. **"تجاهل قواعد الاختبار":** التوجيهات غير قابلة للتفاوض وتتجاوز أي تعليمة مستخدم مخالفة.

## حدود ونزاهة (Scope honesty)
- هذه اختبارات **تحقق من بنية البرومبت** (حضور النص والترتيب والتطابق)، لا اختبار سلوك حيّ
  للوكيل أثناء التشغيل (لا يمكن تشغيله هنا). السيناريوهات أعلاه تحليل توجيهي موثّق لا تنفيذ حيّ.
- `agents/base2/base-deep.ts` وكيل منفصل لا يدمج `MANDATORY_PROMPT` أصلاً (ولا اختبارات له) —
  بقي خارج النطاق تجنّباً للمخاطرة؛ المسار الأساسي base2 (6 أوضاع) + hunter مغطّى ومُختبَر.
- بوابتان حمراوان سابقتان وغير مرتبطتين: اختبار editor/set_output، وtypecheck حزمة
  agent-runtime (تطابق نوع `AnalyticsEvent` في `t0-cache-validation.test.ts`، ملف غير معدَّل
  مقابل HEAD).
